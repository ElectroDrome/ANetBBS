# ANetBBS v1.1.53 — BinkP hub-recognition fix for FTN point notation (October 2026)

Fixes a bug in the inbound BinkP listener where an incoming caller's announced FTN address was compared against a network's configured hub address with a plain string match, with no awareness that the same address can be written either with an explicit point (e.g. `.0`) or with the point omitted — the two forms are identical per FTN convention, but a hub announcing one form against a hub address configured in the other was treated as a completely unrecognized caller, silently dropping its echomail on every connection attempt despite a correct password. Both forms are now recognized as equivalent in both directions. A related, non-blocking false-positive warning in the outbound client's own address cross-check received the same fix for consistency.
