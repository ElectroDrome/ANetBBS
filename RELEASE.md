# ANetBBS v1.1.51 — fsxNet IBLC wire-format and sync fixes (October 2026)

Fixes two issues in the fsxNet IBOL/IBLC inbound sync: a second real-world Last Caller (IBLC) wire format — a pipe-delimited header/data layout framed with bare `BEGIN`/`END` markers, used by at least one real fsxNet peer — was being classified as unrecognized and silently dropped instead of imported; and the sync job had no memory of messages it had already classified as unrelated to IBOL/IBLC, causing it to re-scan and re-skip the same backlog of unrelated traffic on every run instead of just once. A message matching a known IBOL/IBLC shape whose feature toggle happens to be disabled is not affected by the second fix — it's picked up normally as soon as the toggle is turned on.
